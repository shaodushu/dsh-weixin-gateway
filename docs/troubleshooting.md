# 排障与踩坑记录

> 实测踩过的坑，按症状组织。新增经验往这里记，别只留在聊天记录里。

## 症状：网关在跑但收不到任何消息

**原因（最容易漏）**：微信端没有启用 ClawBot 插件。消息不路由到网关。

**解决**：微信 → 我 → 设置 → 插件 → 启用 ClawBot。

## 症状：-14 session timeout

- **真相**：网关进程的 `getUpdates` 长轮询既是拉消息也是**保活心跳**；登录进程退出后 session 被服务端回收。修复：登录成功后**同一进程立即接轮询**。
- **独立测试请求被 -14 拒绝不代表网关状态**：curl / node 单发请求可能被服务端以并发限制拒绝（-14）。判断网关是否工作要看网关日志，不要用独立请求测试。
- **实例互斥**：同一账号两个网关实例同时轮询会互相顶掉对方会话（-14，重新扫码也无效）。机制与锁语义见[使用手册](usage.md#实例互斥同一账号只能一个网关)。

## 症状：每条回复发两遍

**原因**：`WeixinStreamingSender.flush()` 曾同时 queueSend 尾文、又把尾文放进返回的 `textParts`，调用方再发一次 → 每条回复重复（实测"问时间回两条"）。

**解决**：尾文只由调用方统一发一次（flush 只返回不发送）。

## 症状：登录成功但网关不工作

**原因**：`notifyStart` 是启动顺序的一部分——原版 channel 启动时先 `notifyStart` 再轮询，漏掉会跳过服务端启动握手。

## 症状：网关运行中会话突然全部失效

**原因**：扫码登录创建了新 bot 账号（`xxx@im.bot`），旧账号立即失效。daemon / `run` 默认取**最新登录**账号（`accounts-index.json` 末位），若配置固定了旧账号 id 就会空转失效账号。

**解决**：不要固定账号 id，让网关自动取最新登录账号；清理旧账号文件见[使用手册](usage.md#换账号--重新扫码)。

## 其他实测约束

- **`ilink_appid: "bot"` 必须**在 package.json（`readPackageJsonFromDir` 向上查找），否则消息路由异常。
