# 排障与踩坑记录

> 实测踩过的坑，按症状组织。新增经验往这里记，别只留在聊天记录里。

## 症状：网关在跑但收不到任何消息

**原因（最容易漏）**：微信端没有启用 ClawBot 插件。消息不路由到网关。

**解决**：微信 → 我 → 设置 → 插件 → 启用 ClawBot。

## 症状：画图（文生图）要 1-2 分钟甚至更久

**原因**：不是网关慢——图像 API（gpt-image-2）单次生成实测约 60s（波动 45-143s），加上 LLM 决策轮，全程 1-2.5 分钟属正常。

**耗时拆分**（0.3.5+ 日志，`openclaw-YYYYMMDD.log`）：
- `weixin-gateway: tool call generate_image args=...` = 工具调用起始
- `ai-service: generated image` = 生成完成
- 两者之差 = 图像 API 耗时；此前的时间 = LLM 决策轮

**已内置的体验兜底**（0.3.5+）：
- 工具调用时立即回占位"好的，正在生成图片，大概需要 1 分钟左右，请稍候～"
- 图像 API 单次请求 150s 超时（其余 AI 能力 60s），超时回复明确错误，不会无限等待

**仍嫌慢**：换更快的模型或更小尺寸（512x512 明显快于 1024x1024，`AI_IMAGE_MODEL` / generate_image 的 size 参数）。

## 症状：收到"服务开小差了：AI 响应超时 / 任务处理超时"回复

**含义**（0.3.8+ 两层超时，见[使用手册](usage.md#消息处理超时两层保护)）：
- `AI 响应超时（180s 无输出）`：LLM 推理或工具执行连续 180s 无任何事件——多为 AI 网关偶发挂起。日志特征：收到消息后长时间无 `stream delta` / `tool call` 行
- `任务处理超时（>900s）`：单条消息总耗时超 15 分钟——多为 agent 陷入工具循环（如反复执行命令排障）

**处理**：稍后再试即可。底层推理无法中止，超时后可能仍在后台完成（产出不再发送）。频繁出现可调环境变量 `OPENCLAW_ASK_IDLE_TIMEOUT_SEC` / `OPENCLAW_ASK_TIMEOUT_SEC` 后重启网关。

**背景**：0.3.8 前是单一"整轮 180s"预算——多轮工具往返的长时间正常任务（如让 agent 装插件排障，实测 47 次工具调用）会被误杀，且文案"LLM 推理超时"误导为模型挂掉。0.3.8 改为"空闲 + 整轮"两层：活动事件刷新空闲计时，长任务不误杀；文案区分"AI 响应超时 / 任务处理超时"。

## 症状：图片/语音消息没有 AI 描述（只有"已保存到路径"）

**原因**：该 AI 能力未配置（语音转文字缺 `AI_ASR_*`、图像理解缺 `AI_VISION_*`，且无全局 `AI_GATEWAY_*` 兜底）。能力独立判定，一个未配置不影响其他能力。

**解决**：`dsh-weixin setup` 交互式引导逐项配置写入 `.env`；或手动填环境变量（见[使用手册](usage.md#依赖与凭据位置)）。配置后需重启网关进程生效。

## 症状：-14 session timeout

- **真相**：网关进程的 `getUpdates` 长轮询既是拉消息也是**保活心跳**；登录进程退出后 session 被服务端回收。修复：登录成功后**同一进程立即接轮询**。
- **独立测试请求被 -14 拒绝不代表网关状态**：curl / node 单发请求可能被服务端以并发限制拒绝（-14）。判断网关是否工作要看网关日志，不要用独立请求测试。
- **实例互斥**：同一账号两个网关实例同时轮询会互相顶掉对方会话（-14，重新扫码也无效）。机制与锁语义见[使用手册](usage.md#实例互斥同一账号只能一个网关)。

## 症状：每条回复发两遍

**原因**：`WeixinStreamingSender.flush()` 曾同时 queueSend 尾文、又把尾文放进返回的 `textParts`，调用方再发一次 → 每条回复重复（实测"问时间回两条"）。

**解决**：尾文只由调用方统一发一次（flush 只返回不发送）。

## 症状：登录成功但网关不工作

**原因**：`notifyStart` 是启动顺序的一部分——原版 channel 启动时先 `notifyStart` 再轮询，漏掉会跳过服务端启动握手。

## 症状：网关运行中会话突然全部失效

**原因**：扫码登录创建了新 bot 账号（`xxx@im.bot`），旧账号立即失效。daemon / `run` 默认取**最新登录**账号（`accounts-index.json` 末位），若配置固定了旧账号 id 就会空转失效账号。

**解决**：不要固定账号 id，让网关自动取最新登录账号；清理旧账号文件见[使用手册](usage.md#换账号--重新扫码)。

## 其他实测约束

- **`ilink_appid: "bot"` 必须**在 package.json（`readPackageJsonFromDir` 向上查找），否则消息路由异常。
